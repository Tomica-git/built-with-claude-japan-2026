# 気分テンポ日記

毎朝の気分を残し、その日にやりたいこと・興味・任せたい仕事・目標を短い問いで聞いて、記録から「自分の説明書」の下書きを更新する日記です。

開発期間は 2026年11月2日12:00から11月10日14:00（日本時間）です。提出先は [Built with Claude: Japan 2026](https://cerebralvalley.ai/e/built-with-claude-japan2026) です。

## 何を作るか

気分や周りの興味で、優先順位と計画をよく変える。その変わり方を、直す対象ではなく記録にして、自分の傾向が読めるようにします。

朝の流れは次のとおりです。

1. 今朝の気分を、言葉とテンポ（重い / ぼんやり / いつもの朝 / 軽い / 高まる）で置く。
2. 人との距離（ひとりでいたい — 誰かといたい）と、刺激（静かにしていたい — 新しいものが欲しい）を、今朝の位置として残す。内向か外向かの結論にはしない。
3. 短い問いで、やりたいこと、興味、任せたい仕事、目標を一つずつ聞く。問いの途中では Claude を呼ばない。
4. 言葉を先に保存する。そのあと Claude が、今日の受け取り、傾向の要約、自分の説明書の下書きを返す。
5. 傾向では、計画の変わり方と、内向と外向の寄りを見る。記録が一日だけのときは「初日の仮説」とし、性格の結論にしない。

説明書の「あつかい方」は、その日のテンポで予定をどう置くか、までです。

## 誰のためか

まず、これを書く本人のためです。HSS型HSPで、刺激が欲しい気持ちと疲れやすさが同じ日にあり、内向と外向を行き来する。その揺れを、欠陥ではなく今朝のテンポとして残したい、という使い方から始めています。

他の人に配るプロダクトにはしていません。朝に自分で開き、自分の言葉で確かめられることを優先しています。

## このハッカソンの出発点

公式の出発点は二つあります。ひとつは、ひとりが深い知見から紡ぎ出すもの。もうひとつは、人々が手を携えてこそ成し遂げられるもの（多くの人を阻んできた壁を取り払い、日本社会が共有する課題にも応える方向）です。

この日記は、一つ目に置いています。材料は、本人が毎朝すでに知っていることです。気分で計画が動くこと、興味が優先順位を変えること、人と距離を取りたい朝と誰かといたい朝が両方あること。それは一般的な気分アプリの題材ではなく、本人にしか朝ごとに突き合わせられない知見です。説明書が合っているかは、本人が読んで「近い」か「違う」かを言うことでしか分かりません。

## いま動くこと

- ブラウザで朝の入力から、傾向、説明書の下書きまでが一画面で終わる。
- 記録はサーバの `data/` に JSON で残る。同じ日の書き直しは、その日の説明書を二重に足さず、直前の下書きを土台にする。
- Claude API は保存のあと一回だけ。モデルの既定は `claude-sonnet-5-5`（`CLAUDE_MODEL` で変更できる）。
- 診断、治療、薬、医療的な助言は頼まない。画面の脚注に、よりそいホットラインの番号を置いている。

## 動かし方

Node.js 20 以上。

```bash
cp .env.example .env
```

`.env` の `ANTHROPIC_API_KEY` に、自分の Claude API キーを書きます。キーはリポジトリに入れません。

```bash
npm install
npm start
```

ブラウザで <http://127.0.0.1:3000> を開きます。待受は `127.0.0.1` だけです。

別のターミナルで、架空のサンプルを一日分送れます。今日の記録を上書きします。

```bash
npm run sample
```

成功すると、その日が `data/entries.json` に残り、ターミナルと画面の「説明書」に傾向要約と下書きが出ます。

API キーがないときも、入力した言葉は保存されます。傾向と説明書は更新されません。画面にその旨が出ます。キーを入れてから「傾向と説明書を更新する」を押すと、保存済みの言葉でやり直せます。

```bash
npm test
```

テストは保存、依頼の形、失敗しても言葉が残ること、を見ます。朝に使えたかの判断はテストではしません。

## データ

`data/` は日記です。git に含まれません。Issue や PR に、気分の本文を貼らないでください。

## 進め方

目標は一つずつ、[LOOP.md](LOOP.md) の手順で進めます。
